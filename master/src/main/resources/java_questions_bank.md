# بانک جامع سوالات مصاحبه و آزمون تشریحی جاوا و مهندسی نرم‌افزار

این فایل شامل مجموعه‌ای پالایش‌شده، بدون همپوشانی و مرتب‌شده از سوالات تشریحی جاوا و مهندسی نرم‌افزار در سه سطح **Senior**، **Midlevel** و **Junior** به همراه راهنما و پاسخ‌های کامل و استاندارد است.

# سوالات سطح ارشد (Senior)

### 1. در پروژه‌ای با بار پردازشی بالا، چگونه می‌توانید عملکرد Thread Pool در Java را بهینه و کنترل کنید؟
- **راهنما (Hint):** به تاثیر تعداد هسته‌های پردازنده و تفاوت وظایف محاسباتی و ورودی/خروجی توجه کنید.
- **سطح (Level):** Senior

#### پاسخ:
برای بهینه‌سازی عملکرد Thread Pool در جاوا، باید پارامترهای اصلی `ThreadPoolExecutor` را بر اساس نوع بار کاری (Workload) تنظیم کرد:
1. **وظایف محاسباتی (CPU-Bound):** تعداد Threadها باید تقریباً برابر با تعداد هسته‌های پردازنده (`Runtime.getRuntime().availableProcessors() + 1`) باشد تا از Context Switching اضافی جلوگیری شود.
2. **وظایف ورودی/خروجی (I/O-Bound):** تعداد Threadها می‌تواند بیشتر باشد (فرمول تقریبی: `Number of Threads = Number of Cores * (1 + Wait Time / Service Time)`).
3. **انتخاب صف مناسب (Queue Selection):** برای بارهای متوازن از `ArrayBlockingQueue` با ظرفیت مشخص (Bounded Queue) استفاده می‌شود تا از پر شدن حافظه (Memory Leak / OOM) جلوگیری شود.
4. **استراتژی رد درخواست (RejectedExecutionHandler):** در صورت پر شدن صف، استراتژی‌هایی مانند `CallerRunsPolicy` یا `DiscardOldestPolicy` را بر اساس نیازمندی سیستم اعمال می‌کنیم.

### 2. در پروژه‌های بزرگ جاوا چگونه می‌توان با استفاده از Reflection به صورت امن و بهینه کلاس‌ها و متدها را مدیریت کرد؟
- **راهنما (Hint):** در پروژه‌های بزرگ، Reflection می‌تواند باعث مشکلات امنیتی و عملکردی شود.
- **سطح (Level):** Senior

#### پاسخ:
استفاده از Reflection در پروژه‌های بزرگ باید همراه با تمهیدات زیر باشد:
1. **بهینه‌سازی عملکرد (Performance Caching):** متاداده‌های فراخوانی‌شده مانند `Method`، `Field` و `Class` را در حافظه کش (مانند `ConcurrentHashMap`) ذخیره می‌کنیم تا از فراخوانی تکراری و سنگین Reflection جلوگیری شود.
2. **امنیتی (Security & Access Control):** از تغییر دسترسی فیلدهای `private` تا حد امکان پرهیز می‌کنیم و در صورت نیاز، دسترسی‌ها را محدود و اعتبار‌سنجی می‌کنیم.
3. **جایگزین‌های مدرن:** در صورت امکان از `MethodHandle` یا کدژنسازی دینامیک (Bytecode Generation مانند ByteBuddy یا CGLIB) استفاده می‌کنیم که نسبت به Reflection سنتی سرعت بسیار بیشتری دارند.

### 3. در چه شرایطی استفاده از Java Memory Model (JMM) اهمیت حیاتی پیدا می‌کند و چگونه می‌توان مشکلات مرتبط با آن را حل کرد؟
- **راهنما (Hint):** به تاثیر اجرای همزمان و اشتراک داده‌ها در محیط چندریسمانی فکر کنید.
- **سطح (Level):** Senior

#### پاسخ:
مفهوم JMM در برنامه‌نویسی همزمان (Multithreading) برای تضمین **Visibility**، **Atomicity** و **Ordering** حیاتی است:
1. **Visibility (دیدپذیری):** تغییرات متغیر در یک Thread ممکن است در Cache پردازنده بماند و برای Thread دیگر قابل دیدن نباشد. حل با کلیدواژه `volatile` یا ساختارهای Synchronized.
2. **Instruction Reordering:** پردازنده و کامپایلر ممکن است دستورات را برای بهینه‌سازی جابه‌جا کنند. روابط Happens-Before در JMM جلوگیری از Reordering غیرمجاز را تضمین می‌کند.
3. **Atomicity (اتمیک بودن):** عملیات‌های چندمرحله‌ای (مانند `count++`) اتمیک نیستند. حل با استفاده از کلاس‌های `AtomicInteger` / `AtomicReference` (عملیات‌های CAS) یا قفل‌ها (`ReentrantLock`).

### 4. در طراحی معماری یک سیستم توزیع‌شده با حجم بالای داده، چه الگوهایی را برای ارتقاء مقیاس‌پذیری و تحمل‌پذیری خطا پیشنهاد می‌دهید؟
- **راهنما (Hint):** به تفکیک مسئولیت‌ها و مدیریت خطا در محیط توزیع‌شده توجه کنید.
- **سطح (Level):** Senior

#### پاسخ:
برای ارتقای مقیاس‌پذیری و پایداری در سیستم‌های توزیع‌شده داده‌محور:
1. **معماری رویدادمحور (Event-Driven Architecture) و Event Sourcing:** استفاده از Message Brokerها (مانند Kafka) برای ارتباط غیرهمزمان و کاهش Coupling.
2. **الگوی CQRS (Command Query Responsibility Segregation):** جداسازی لایه‌های نوشتن داده (Command) و خواندن داده (Query) برای بهینه‌سازی مستقل هر لایه.
3. **الگوی Saga:** مدیریت تراکنش‌های توزیع‌شده بین چند میکروسرویس بدون نیاز به Two-Phase Commit (2PC) با استفاده از روش‌های Orchestration یا Choreography.
4. **الگوی Circuit Breaker & Bulkhead:** جلوگیری از انتشار خطا بین سرویس‌ها (با ابزارهایی مثل Resilience4j).

### 5. برای بهبود کارایی یک سرویس جاوا که با تاخیر بالا در پاسخ‌دهی مواجه است، چه روش‌هایی را در سطح معماری و کد پیشنهاد می‌کنید؟
- **راهنما (Hint):** به تفکیک راهکارهای سطح معماری و کد توجه کنید.
- **سطح (Level):** Senior

#### پاسخ:
راهکارهای بهبود کارایی در دو سطح:
- **در سطح کد:**
  1. بهینه‌سازی الگوریتم‌ها و کاهش تخصیص حافظه غیرضروری.
  2. استفاده از Caching موثر (Cache-Aside Pattern با Redis).
  3. غیرهمزمان‌سازی پردازش‌های زمان‌بر با استفاده از CompletableFuture یا صف‌های پیام.
  4. بهینه‌سازی کوئری‌های دیتابیس، رفع مشکل N+1 و استفاده از ایندکس‌گذاری صحیح.
- **در سطح معماری:**
  1. مقیاس‌پذیری افقی (Horizontal Scaling) و استفاده از Load Balancer.
  2. جداسازی دیتابیس خواندن و نوشتن (Read Replicas).
  3. استفاده از CDN و API Gateway برای مدیریت درخواست‌ها.

### 6. پیاده‌سازی یک Custom ClassLoader در جاوا چه کاربردهایی دارد و چه چالش‌هایی در مدیریت حافظه و امنیت ایجاد می‌کند؟
- **راهنما (Hint):** ClassLoaderها می‌توانند رفتار بارگذاری کلاس‌ها را تغییر دهند و باید با دقت پیاده‌سازی شوند.
- **سطح (Level):** Senior

#### پاسخ:
کاربردها و چالش‌های Custom ClassLoader:
- **کاربردها:** بارگذاری دینامیک کلاس‌ها در سیستم‌های پلاگینی، رمزگشایی کلاسبایت‌های رمزگذاری‌شده در زمان اجرا، ایزوله‌سازی نسخه‌های مختلف یک کتابخانه در یک JVM.
- **چالش‌ها:**
  1. **Memory Leak (نشت حافظه):** اگر ClassLoader و کلاس‌های بارگذاری‌شده به‌درستی Unload نشوند، ارجاع‌ها در Metaspace مانع از Garbage Collection شده و منجر به `OutOfMemoryError: Metaspace` می‌شوند.
  2. **مسائل امنیتی:** دور زدن مکانیزم‌های امنیتی استاندارد JVM و Delegation Model خروجی کد غیرمطمئن.

### 7. چگونه می‌توان با استفاده از مانیتورینگ، مشکلات Bottleneck را در یک سیستم Java شناسایی و تحلیل کرد؟
- **راهنما (Hint):** به اهمیت جمع‌آوری داده‌های عملکردی و تحلیل آن‌ها توجه کنید.
- **سطح (Level):** Senior

#### پاسخ:
برای شناسایی گلوگاه‌ها (Bottleneck):
1. **جمع‌آوری متریک‌ها در لایه‌های مختلف:**
   - **سطح JVM:** پایش مصرف Heap، تعداد و زمان اجرای Garbage Collection (GC Pauses)، تعداد Threadهای متوقف (Blocked/Waiting).
   - **سطح برنامه:** زمان پاسخ REST APIها، نرخ خطا (Error Rate)، نرخ درخواست (Throughput).
   - **سطح دیتابیس:** پایش Connection Pool، کوئری‌های کند (Slow Queries) و قفل‌ها.
2. **ابزارها:** استفاده از APMها (مانند Elastic APM، Dynatrace، New Relic) و ابزارهای مانیتورینگ Prometheus & Grafana.
3. **تحلیل:** بررسی Thread Dump برای یافتن Deadlock یا Thread contention و Heap Dump برای یافتن Memory Leak با ابزارهایی مانند JProfiler یا VisualVM.

### 8. در مواجهه با Memory Leak در یک سرویس جاوا، مراحل شناسایی و رفع آن را شرح دهید.
- **راهنما (Hint):** به ابزارهای پروفایل و بررسی Heap توجه داشته باشید.
- **سطح (Level):** Senior

#### پاسخ:
مراحل عیب‌یابی Memory Leak:
1. **ثبت لاگ و دریافت Heap Dump:** تنظیم پارامتر `-XX:+HeapDumpOnOutOfMemoryError` در JVM برای گرفتن خودکار فایل Dump هنگام رخ دادن OOM.
2. **تحلیل فایل Heap Dump:** استفاده از ابزارهایی مانند Eclipse MAT (Memory Analyzer Tool) یا JProfiler برای شناسایی Dominator Tree و اشیایی که بیشترین حجم حافظه را اشغال کرده‌اند.
3. **شناسایی GC Root:** بررسی مسیر ارجاع اشیا به GC Root (مانند فیلدهای static، ThreadLocalهای پاک‌نشده یا Collectionهای دائمی).
4. **اصلاح کد:** پاکسازی ارجاعات، متوقف کردن Listeners/Observers و فراخوانی `.remove()` روی ThreadLocalها.

### 9. در پروژه‌های بزرگ، چگونه استراتژی تست خودکار را برای کاهش هزینه نگهداری و افزایش کیفیت توسعه می‌دهید؟
- **راهنما (Hint):** به سطوح مختلف تست و نقش آن‌ها در چرخه توسعه توجه کنید.
- **سطح (Level):** Senior

#### پاسخ:
استراتژی هرم تست (Test Pyramid):
1. **تست‌های واحد (Unit Tests - پایه هرم):** بیشترین حجم تست‌ها (حداقل ۷۰-۸۰ درصد) باید تست واحد سریع و مستقل بدون وابستگی به زیرساخت واقعی باشند.
2. **تست‌های یکپارچگی (Integration Tests - لایه وسط):** اعتبارسنجی تعامل اجزا با دیتابیس یا سرویس‌های جانبی با استفاده از Testcontainers.
3. **تست‌های End-to-End (نوک هرم):** تعداد محدود برای سناریوهای کلیدی کسب‌وکار.
4. **اتوماسیون در CI/CD:** اجرای خودکار تست‌ها در هر Merge Request و ارزیابی کد با ابزارهای Code Coverage (مانند JaCoCo) و SonarQube.

### 10. در تست اتوماتیک یک سیستم توزیع‌شده، چه چالش‌هایی وجود دارد و چگونه باید آن‌ها را مدیریت کرد؟

- **سطح (Level):** Senior

#### پاسخ:
چالش‌ها و راهکارها:
1. **عدم قطعیت و تاخیر شبکه (Flakiness & Network Latency):** مدیریت با استفاده از Retry Mechanisms و Awaitility برای انتظار هوشمندانه.
2. **مدیریت وضعیت داده‌ها (Data State):** ایزوله‌سازی داده‌های تست و Reset کردن دیتابیس‌ها یا استفاده از Containerهای مجزا برای هر اجرا.
3. **وابستگی به سرویس‌های دیگر:** استفاده از Service Virtualization / Mock Serverها (مانند WireMock) و Consumer-Driven Contract Testing (با ابزار Pact).

### 11. در طراحی یک RESTful API با حجم بالای درخواست، چه اقداماتی برای افزایش کارایی و امنیت پیشنهاد می‌کنید؟

### 12. در چه شرایطی استفاده از SOAP نسبت به REST در پروژه‌های جاوا ترجیح داده می‌شود؟

### 13. در پروژه‌ای با استفاده از Spring Boot، چگونه می‌توانید Dependency Injection را بهینه و قابل تست نگه دارید؟

بهترین روش‌ها:
1. **استفاده از Constructor Injection به جای Field Injection (`@Autowired` روی فیلد):** این کار باعث صریح شدن وابستگی‌ها، امکان تعریف فیلدها به صورت `final` (تغییرناپذیری) و سهولت ساخت شیء در تست‌های Unit بدون نیاز به Spring Context می‌شود.
2. **پرهیز از وابستگی چرخه‌ای (Circular Dependency):** طراحی بر اساس اصول SOLID و استفاده از الگوی Facade یا Events در صورت نیاز.
3. **استفاده از Interfaceها:** تزریق اینترفیس به جای کلاس‌های پیاده‌سازی جهت Loose Coupling.

### 15. در چه شرایطی استفاده از Singleton Pattern می‌تواند مشکلات جدی در پروژه ایجاد کند و راه‌حل چیست؟
- **راهنما (Hint):** به تاثیر Singleton در تست‌پذیری و همزمانی توجه کنید.
- **سطح (Level):** Senior

#### پاسخ:
مشکلات Singleton سنتی:
1. **ایجاد Global State و سخت شدن تست‌پذیری:** به دلیل داشتن Private Constructor و متد Static، جایگزین کردن آن با Mock در Unit Test دشوار است.
2. **تنگنا در محیط‌های چندریسمانی (Thread Safety Issues):** اگر وضعیت (State) متغیر داشته باشد، موجب Race Condition می‌شود.
3. **نقض اصل SRP:** کلاس هم مدیریت لایف‌سایکل خود را بر عهده دارد هم منطق کاری‌اش را.

### 16. در مدیریت منابع و بهینه‌سازی مصرف حافظه در جاوا، چه تکنیک‌هایی را به کار می‌برید؟
- **راهنما (Hint):** به اهمیت آزادسازی منابع و مدیریت چرخه عمر آن‌ها توجه کنید.

#### پاسخ:
تکنیک‌های کلیدی:
1. **استفاده از ساختار Try-with-Resources:** برای بستن خودکار منابعی که `AutoCloseable` هستند (مانند Files، DB Connections، Sockets).
2. **مدیریت صحیح ThreadLocal:** همواره فراخوانی `.remove()` در بلاک `finally` جهت جلوگیری از Memory Leak در Thread Poolها.
3. **پرهیز از فیلدها و Collectionهای Static بزرگ:** پاکسازی اشیای بدون استفاده.
4. **استفاده از StringBuilder و Primitive Types:** جهت کاهش بار اشیای موقت روی Heap.

### 18. چه تفاوت‌هایی بین HashMap و ConcurrentHashMap وجود دارد و در چه شرایطی باید از هرکدام استفاده کرد؟

#### پاسخ:
تفاوت‌ها:
1. **Thread Safety:** کلاس `HashMap` برای محیط‌های تک‌نخی طراحی شده و Thread-Safe نیست. `ConcurrentHashMap` کاملاً Thread-Safe است.
2. **پیاده‌سازی همزمانی:** در `ConcurrentHashMap` به جای قفل کردن کل Map (مانند `Collections.synchronizedMap`)، از قفل در سطح Bucketها (Bucket-level locking / CAS operations) استفاده می‌شود که کارایی بسیار بالاتری در همزمانی دارد.
3. **مقادیر null:** کلید یا مقدار `null` در `HashMap` مجاز است اما در `ConcurrentHashMap` غیرمجاز بوده و باعث `NullPointerException` می‌شود.

# سوالات سطح میان‌رده (Midlevel)

### 1. در جاوا، تفاوت کلیدی بین کلاس‌های انتزاعی (abstract class) و اینترفیس‌ها (interface) چیست و در چه شرایطی از هرکدام استفاده می‌شود؟
- **راهنما (Hint):** به تفاوت‌های ارث‌بری، پیاده‌سازی متدها و نگهداری وضعیت فکر کنید.
- **سطح (Level):** Midlevel

#### پاسخ:
تفاوت‌های کلیدی:
1. **ارث‌بری:** یک کلاس جاوا تنها می‌تواند از یک `abstract class` ارث‌بری کند (تک میراثی)، اما می‌تواند چندین `interface` را پیاده‌سازی کند.
2. **وضعیت (State):** کلاس انتزاعی می‌تواند فیلدهای نمونه (Instance Variables) غیرثابت داشته باشد و وضعیت را نگهداری کند، اما متغیرهای اینترفیس به صورت پیش‌فرض `public static final` (ثابت) هستند.
3. **متدها:** کلاس انتزاعی می‌تواند متدهای با بدنه و بدون بدنه داشته باشد. اینترفیس‌ها عمدتاً قرارداد هستند (هرچند از جاوا ۸ متدهای `default` و `static` اضافه شده‌اند).
- **کاربرد:** اگر کد مشترک و رابطه `Is-A` قوی داریم از کلاس انتزاعی، و اگر قرارداد رفتاری مشترک بین کلاس‌های بی‌ارتباط (رابطه `Can-Do`) داریم از اینترفیس استفاده می‌کنیم.

---

### 2. فرض کنید یک متد در جاوا دارید که باید همزمان توسط چند Thread اجرا شود. چه راهکاری برای جلوگیری از Race Condition پیشنهاد می‌دهید؟
- **راهنما (Hint):** به مدیریت منابع مشترک در سناریوی چندنخی فکر کنید.
- **سطح (Level):** Midlevel

#### پاسخ:
راهکارهای جلوگیری از Race Condition:
1. **استفاده از کلیدواژه `synchronized`:** روی متد یا بلاک کد مشخصی که به منبع مشترک دسترسی دارد.
2. **استفاده از قفل‌های صریح (`ReentrantLock`):** انعطاف‌پذیری بیشتر نسبت به synchronized (مانند tryLock با Time-out).
3. **استفاده از ساختارهای داده Thread-Safe:** مانند `ConcurrentHashMap` یا `CopyOnWriteArrayList`.
4. **استفاده از متغیرهای اتمیک:** مانند `AtomicInteger` برای عملیات‌های ساده شمارش بدون نیاز به قفل‌گذاری سنگین.

---

### 3. تفاوت اصلی بین ArrayList و LinkedList در جاوا چیست و در چه سناریویی هرکدام را ترجیح می‌دهید؟
- **راهنما (Hint):** به نحوه ذخیره‌سازی داده‌ها و کارایی عملیات مختلف دقت کنید.
- **سطح (Level):** Midlevel

#### پاسخ:
تفاوت در پیاده‌سازی و کارایی:
1. **ArrayList:** بر پایه آرایه پویا (Dynamic Array) است. دسترسی تصادفی (`get(index)`) بسیار سریع و از مرتبه $O(1)$ است. اما افزودن یا حذف عنصر در ابتدا یا وسط آرایه به دلیل نیاز به جابه‌جایی عناصر از مرتبه $O(n)$ است.
2. **LinkedList:** بر پایه لیست پیوندی دوطرفه (Doubly Linked List) است. افزودن یا حذف عنصر در ابتدا یا انتها بسیار سریع و $O(1)$ است. اما دسترسی با ایندکس نیاز به پیمایش دارد و $O(n)$ است.
- **انتخاب:** اگر خواندن زیاد داریم `ArrayList`؛ اگر درج و حذف فراوان در ابتدا/انتها داریم `LinkedList`.

---

### 4. در یک سیستم سفارش آنلاین، برای مدیریت صف سفارش‌ها کدام ساختار داده را پیشنهاد می‌دهید؟
- **راهنما (Hint):** به ترتیب پردازش داده‌ها توجه کنید.
- **سطح (Level):** Midlevel

#### پاسخ:
ساختار داده پیشنهادی:
- **`Queue` (مانند `ArrayDeque` یا `LinkedList`):** برای پردازش سفارش‌ها به ترتیب ورود (FIFO - First In First Out).
- **`PriorityQueue`:** در صورتی که سفارش‌ها دارای اولویت باشند (مثلاً سفارش‌های کاربران VIP زودتر پردازش شوند).
- **در محیط‌های چندریسمانی:** استفاده از صف‌های همزمان مانند `ArrayBlockingQueue` یا `ConcurrentLinkedQueue` برای مدیریت ایمن تولیدکنندگان و مصرف‌کنندگان.

---

### 5. در چه شرایطی استفاده از HashMap نسبت به TreeMap در جاوا مناسب‌تر است؟
- **راهنما (Hint):** به نیاز به ترتیب کلیدها و سرعت عملیات توجه کنید.
- **سطح (Level):** Midlevel

#### پاسخ:
مقایسه HashMap و TreeMap:
- **`HashMap`:** عملیات‌های اصلی (`get`, `put`, `remove`) را در زمان ثابت $O(1)$ انجام می‌دهد. کلیدها هیچ ترتیب مشخصی ندارند. برای سناریوهایی که فقط سرعت جستجو و درج بر اساس کلید مهم است، `HashMap` بهترین گزینه است.
- **`TreeMap`:** بر پایه Red-Black Tree پیاده‌سازی شده و کلیدها را به صورت مرتب‌شده نگهداری می‌کند. زمان عملیات‌ها $O(\log n)$ است. زمانی استفاده می‌شود که به پیمایش مرتب کلیدها نیاز داشته باشیم.

### 6. تفاوت بین Abstraction و Encapsulation در برنامه‌نویسی شی‌گرا چیست؟
- **راهنما (Hint):** به نقش کلاس‌ها و اینترفیس‌ها توجه کنید.
- **سطح (Level):** Midlevel

#### پاسخ:
تفاوت دو مفهوم:
- **Abstraction (انتزاع):** پنهان‌سازی **پیچیدگی‌های پیاده‌سازی** و نمایش تنها قابلیت‌های ضروری به کاربر خارج از کلاس (تمرکز روی "چه کاری انجام می‌شود"). با اینترفیس‌ها و کلاس‌های انتزاعی پیاده‌سازی می‌شود.
- **Encapsulation (کپسوله‌سازی):** گروه‌بندی داده‌ها (فیلدها) و متدها در یک واحد متمرکز (کلاس) و محدود کردن **دسترسی مستقیم به داده‌ها** (تمرکز روی "چگونه داده‌ها محافظت می‌شوند"). با تعریف فیلدهای `private` و متدهای `getter/setter` پیاده‌سازی می‌شود.

### 7. در چه شرایطی باید از کلاس StringBuilder به جای String در جاوا استفاده کرد؟
- **راهنما (Hint):** به تغییرپذیری رشته‌ها توجه کنید.
- **سطح (Level):** Midlevel

#### پاسخ:
دلیل استفاده از StringBuilder:
اشیای کلاس `String` غیرقابل تغییر (Immutable) هستند. هر بار الحاق رشته (مانند `s += "a"`) یک شیء جدید در حافظه ساخته می‌شود که در حلقه‌ها باعث کندی شدید و مصرف زیاد حافظه Heap می‌گردد.
`StringBuilder` یک رشته تغییرپذیر (Mutable) است و الحاق رشته‌ها را در همان بفر موجود انجام می‌دهد.
- **نکته:** اگر همزمانی چندریسمانی مطرح باشد از `StringBuffer` (که Thread-Safe است) و در حالت عادی از `StringBuilder` (که سریع‌تر است) استفاده می‌شود.

### 8. در Spring Framework، تفاوت استفاده از `@Component` و `@Service` چیست و چه زمانی هرکدام را به کار می‌برید؟
- **راهنما (Hint):** به نقش معنایی annotationها در معماری فکر کنید.
- **سطح (Level):** Midlevel

#### پاسخ:
تفاوت انوتیشن‌ها:
- **`@Component`:** انوتیشن پایه و عمومی Spring برای معرفی یک کلاس به عنوان یک Spring Bean به IoC Container است.
- **`@Service`:** یک Stereotype تخصصی‌تر بر پایه `@Component` است که برای لایه منطق کسب‌وکار (Business Logic Layer) استفاده می‌شود. استفاده از آن علاوه بر صراحت معنایی در معماری، امکان اضافه شدن رفتارهای خاص لایه سرویس (مانند Aspectهای امنیتی یا تراکنشی) را فراهم می‌کند.

### 9. در Spring Boot چگونه می‌توان یک تنظیمات (Configuration) را برای محیط‌های مختلف (مثلاً توسعه و تولید) جداسازی کرد؟
- **راهنما (Hint):** به سفارشی‌سازی تنظیمات بر اساس محیط فکر کنید.
- **سطح (Level):** Midlevel

#### پاسخ:
استفاده از قابلیت **Profiles**:

### 10. در طراحی یک RESTful Web Service با جاوا، چگونه می‌توانید نسخه‌بندی (Versioning) API را پیاده‌سازی کنید؟

### 11. تفاوت کلیدی بین REST و SOAP در طراحی سرویس‌های وب چیست؟

### 13. تفاوت بین متد `equals` و `==` در جاوا چیست و چه زمانی باید از هرکدام استفاده کرد؟

- **سطح (Level):** Midlevel

#### پاسخ:
تفاوت دو عملگر:
- **اپراتور `==`:** آدرس حافظه (Reference) دو شیء را مقایسه می‌کند تا ببیند آیا هر دو به یک شیء اشاره دارند یا خیر (در انواع اولیه یا Primitive، مقدار آن‌ها را مقایسه می‌کند).
- **متد `equals()`:** محتوای منطقی (Value) دو شیء را مقایسه می‌کند (در صورت Override شدن متد در کلاس مربوطه مانند String، Integer و غیره).

### 14. فرض کنید یک لیست از رشته‌ها دارید و می‌خواهید فقط موارد یکتا را نگه دارید. چه ساختاری در جاوا پیشنهاد می‌دهید و چرا؟
- **راهنما (Hint):** به ساختارهای داده‌ای که تکرار را حذف می‌کنند فکر کنید.
- **سطح (Level):** Midlevel

#### پاسخ:
استفاده از مجموعه **`Set`** (به طور مشخص `HashSet` یا `LinkedHashSet`):
- **`HashSet`:** عناصر تکراری را خودکار حذف می‌کند و سرعت بالایی ($O(1)$) دارد، اما ترتیب درج را حفظ نمی‌کند.
- **`LinkedHashSet`:** علاوه بر حذف تکرار و سرعت بالا، ترتیب ورود عناصر را نیز حفظ می‌کند.
- **تبدیل سریع:** `Set<String> uniqueSet = new LinkedHashSet<>(originalList);`

### 15. در شی‌گرایی جاوا، تفاوت بین ترکیب (Composition) و وراثت (Inheritance) چیست و چه زمانی هرکدام را ترجیح می‌دهید؟
- **راهنما (Hint):** به تفاوت ساختاری و انعطاف‌پذیری در طراحی فکر کنید.
- **سطح (Level):** Midlevel

#### پاسخ:
تفاوت و کاربرد:
- **وراثت (Inheritance):** رابطه `Is-A` (مانند Dog is an Animal). کلاس فرزند تمام رفتارها و داده‌های کلاس والد را ارث می‌برد. باعث دپندرسی شدید (Tight Coupling) می‌شود.
- **ترکیب (Composition):** رابطه `Has-A` (مانند Car has an Engine). یک کلاس نمونه‌ای از کلاس دیگر را به عنوان فیلد نگه می‌دارد. باعث انعطاف‌پذیری زیاد و Loose Coupling می‌شود.
- **اصل طراحی:** همواره "Composition over Inheritance" ترجیح داده می‌شود مگر اینکه رابطه `Is-A` واقعی و دائمی وجود داشته باشد.

### 16. تفاوت بین HashMap و ConcurrentHashMap در چیست و چه زمانی باید از هرکدام استفاده شود؟
- **راهنما (Hint):** به کاربردهای نقشه‌ها در محیط چندریسمانی توجه کن.
- **سطح (Level):** Midlevel

#### پاسخ:
تفاوت اصلی:
`HashMap` برای محیط‌های تک‌نخی مناسب است و در محیط‌های چندریسمانی همزمان منجر به Race Condition و صدمه به دیتابایپلاین می‌شود.
`ConcurrentHashMap` کاملاً Thread-Safe است و به جای قفل کردن کل Map، از سیستم قفل‌گذاری خرد در سطح Segment/Bucket استفاده می‌کند که همزمانی بالا را با کارایی عالی فراهم می‌سازد. در این کلاس کلید یا مقدار null مجاز نیست.

### 17. در یک سیستم توزیع‌شده، چه روشی برای مدیریت Session کاربران پیشنهاد می‌دهید و چرا؟

نحوه کار GC:

# سوالات سطح مقدماتی (Junior)

### 1. در جاوا، تفاوت بین متغیرهای local و instance چیست؟
- **راهنما (Hint):** به حوزه‌ی دید و مدت زمان عمر متغیرها توجه کن.
- **سطح (Level):** Junior

#### پاسخ:
تفاوت متغیرهای Local و Instance:
1. **محل تعریف:** متغیر Local داخل متد، بلوک یا سازنده تعریف می‌شود؛ متغیر Instance داخل کلاس اما خارج از متدها تعریف می‌شود.
2. **محدوده دید (Scope):** متغیر Local فقط داخل همان متد/بلوک قابل دسترسی است؛ متغیر Instance در تمام متدهای کلاس دسترسی‌پذیر است.
3. **طول عمر:** متغیر Local با اتمام اجرای متد از بین می‌رود؛ متغیر Instance تا زمانی که شیء مربوطه در حافظه وجود دارد زنده است.
4. **مقداردهی اولیه:** متغیر Local مقدار اولیه خودکار ندارد و قبل از استفاده باید مقداردهی شود؛ متغیر Instance مقدار پیش‌فرض (مانند 0 یا null) می‌گیرد.

### 2. فرض کنید می‌خواهید اطلاعات کاربران را در یک آرایه ذخیره کنید. اگر تعداد کاربران در زمان اجرا مشخص نباشد، از چه ساختاری در جاوا استفاده می‌کنید؟ چرا؟

- **سطح (Level):** Junior

#### پاسخ:
استفاده از **`ArrayList`** (یا سایر مجموعه‌های پویا):
- **دلیل:** آرایه‌های معمولی در جاوا دارای اندازه ثابت هستند و پس از تعریف نمی‌توان طول آن‌ها را تغییر داد.
`ArrayList` بر پایه آرایه پویا پیاده‌سازی شده و با اضافه شدن عناصر جدید، اندازه خود را به صورت خودکار افزایش می‌دهد.

### 3. در یک پروژه‌ی ساده، برای جلوگیری از تکرار کد، چگونه از متدها استفاده می‌کنید؟
- **راهنما (Hint):** به مفهوم DRY و نقش متدها در سازماندهی کد فکر کن.

طبق اصل **DRY (Don't Repeat Yourself)**:
کدهای تکراری را در قالب متدهای مجزا بسته‌بندی کرده و در نقاط مختلف برنامه آن متدها را فراخوانی می‌کنیم. این کار باعث افزایش خوانایی، کاهش خطا و سهولت در نگهداری و تغییر کد در آینده می‌شود.

### 4. در جاوا چگونه می‌توان یک شیء را از روی یک کلاس ساخت؟

### 5. چرا بهتر است در برنامه‌نویسی شیءگرا، متغیرهای کلاس را private تعریف کنیم؟
- **راهنما (Hint):** به اصل کپسوله‌سازی فکر کن.
- **سطح (Level):** Junior

#### پاسخ:
جهت رعایت اصل **Encapsulation (کپسوله‌سازی)**:
تعریف متغیرها به صورت private باعث جلوگیری از دسترسی و تغییر مستقیم داده‌ها از بیرون کلاس می‌شود. دسترسی تنها از طریق متدهای getter و setter تحت کنترل کلاس انجام می‌گیرد که امنیت و صحت داده‌ها را تضمین می‌کند.

### 6. در صورتی که بخواهید اطلاعات کاربران را بر اساس شناسه (id) به سرعت جستجو کنید، کدام ساختار داده‌ای را در جاوا انتخاب می‌کنید و چرا؟

#### پاسخ:
استفاده از **`HashMap<K, V>`**:
در این ساختار داده، شناسه کاربر به عنوان کلید (Key) و شیء کاربر به عنوان مقدار (Value) ذخیره می‌شود. به دلیل استفاده از جدول هش (Hashing)، سرعت جستجو بر اساس کلید از مرتبه زمانی ثابت $O(1)$ و بسیار سریع است.

### 7. تفاوت بین حلقه for و while در جاوا چیست و چه زمانی از هرکدام استفاده می‌کنید؟

- **سطح (Level):** Junior

#### پاسخ:
تفاوت و زمان کاربرد:
- **حلقه `for`:** زمانی استفاده می‌شود که **تعداد تکرار** حلقه از قبل مشخص باشد (دارای شمارنده، شرط و گام حرکت است).
- **حلقه `while`:** زمانی استفاده می‌شود که **تعداد تکرار مشخص نباشد** و حلقه تا زمان برقرار بودن یک شرط خاص باید ادامه یابد.

### 8. فرض کنید باید لیستی از اعداد را به صورت صعودی مرتب کنید. از کدام الگوریتم ساده می‌توانید استفاده کنید و چرا؟
- **راهنما (Hint):** به الگوریتم‌های مرتب‌سازی پایه‌ای فکر کن.

استفاده از الگوریتم **Bubble Sort (مرتب‌سازی حباب‌دار)** یا **`Collections.sort()`**:
- برای درک ساده و کدهای آموزشی، Bubble Sort با مقایسه دوتایی عناصر مجاور و جابه‌جایی آن‌ها پیاده‌سازی ساده‌ای دارد.
- در کدهای واقعی جاوا، از متد آماده `Collections.sort()` یا `Arrays.sort()` استفاده می‌شود که کارایی بسیار بالایی دارند.

### 9. در یک پروژه ساده، اگر با خطای NullPointerException مواجه شدید، چگونه آن را شناسایی و رفع می‌کنید؟
- **راهنما (Hint):** به دلایل بروز خطا و نحوه بررسی مقدار متغیرها توجه کن.
- **سطح (Level):** Junior

#### پاسخ:
شناسایی و رفع NullPointerException:
1. **شناسایی:** بررسی Stack Trace خطا برای پیدا کردن شماره دقیق خطی که خطا در آن رخ داده است.
2. **علت:** سعی در فراخوانی متد یا فیلد روی متغیری که مقدار آن `null` است.
3. **رفع خطا:** بررسی مقدار متغیر قبل از استفاده با شرط `if (obj != null)`، استفاده از `Objects.requireNonNull()` یا استفاده از کلاس `Optional`.

### 10. اگر بخواهید اطلاعات یک لیست را به صورت معکوس نمایش دهید، چه روشی را در جاوا پیشنهاد می‌دهید؟

- **سطح (Level):** Junior

#### پاسخ:
روش‌های معکوس کردن لیست:
1. **استفاده از متد آماده:** `Collections.reverse(list);` که عناصر لیست را معکوس می‌کند.
2. **پیمایش از انتها:** استفاده از حلقه `for` که از `list.size() - 1` تا `0` معکوس پیمایش می‌کند.
